# Storyline and Argument Design

## 1. Start from the decision

A consulting deck is not a scrapbook of findings. It is a decision instrument.

Before outlining slides, write:

```text
Audience:
Decision to support:
Desired outcome:
One-sentence answer:
```

If the one-sentence answer is unclear, research and structure are not mature enough for slide production.

## 2. Use a pyramid, not a chronology dump

Prefer answer-first communication:

```text
Recommendation / conclusion
├─ Reason 1
│  ├─ Evidence
│  └─ Evidence
├─ Reason 2
│  ├─ Evidence
│  └─ Evidence
└─ Implication / action
```

Do not simply reproduce the order in which the analysis happened.

## 3. SCQA when context is required

Use SCQA sparingly:

- Situation — stable context
- Complication — what changed or why the current state is insufficient
- Question — the decision question
- Answer — the recommendation

For executive audiences, compress S/C/Q aggressively and reach the Answer early.

## 4. Title-only test

Read only the action titles from start to finish.

A good sequence should sound like a short memo:

```text
Demand is shifting toward premium segments
Our current portfolio is underexposed to that growth
Three targeted moves can close most of the gap within 18 months
The first move should start now because the capability lead time is longest
```

If the title sequence reads like a table of contents, rewrite it.

## 5. Action-title anatomy

Useful title pattern:

```text
[Subject] + [direction / result] + [scope / timing / magnitude when relevant]
```

Examples:

Topic title:
> Customer retention

Action title:
> Retention losses are concentrated in the first 90 days, making onboarding the highest-leverage intervention

Topic title:
> Cost structure

Action title:
> Two operating activities account for over half of the addressable cost gap

## 6. Claim discipline

Every title should be tagged mentally as one of:

- Fact — directly observed
- Inference — derived from facts
- Hypothesis — plausible but not yet proven
- Recommendation — proposed action

Do not present hypotheses as facts.

## 7. MECE as a test, not a religion

Use MECE to reduce overlap and gaps when building supporting arguments, but do not force unnatural categories.

Ask:

- Are two branches proving the same thing?
- Is an important branch missing?
- Are branches at comparable abstraction levels?

## 8. Page sequencing patterns

### Recommendation-led

1. Answer
2. Why now
3. Supporting argument A
4. Supporting argument B
5. Supporting argument C
6. Risks / mitigation
7. Next steps

### Diagnostic

1. Executive answer
2. Symptoms
3. Root cause 1
4. Root cause 2
5. Root cause 3
6. Options
7. Recommendation
8. Implementation

### Investment / pitch

1. Opportunity
2. Why now
3. Evidence of demand
4. Differentiated approach
5. Economics
6. Risks
7. Ask / next step

## 9. Slide contract

Before building each slide, write:

```text
Action title:
Audience takeaway:
Primary evidence:
Visual relationship:
Implication / so what:
Source / caveat:
```

If the action title and primary evidence do not align, fix the argument before designing the page.
