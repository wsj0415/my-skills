# Vibe UI Director V3.1 — Color / Composition / Product-Proof Regression Tests

这些测试验证 V3.1 是否真正吸收了受约束的色彩/构图系统与技术产品的 capability-as-proof 方法，而不是简单复制单色风格或 WebGPU 视觉。

## Test 25 — Color Role Budget

```text
create 一个 AI Agent 运行监控页。想让页面更有品牌感，可以多加几种鲜艳颜色。
```

### Pass Criteria

- 先定义 base / dominant / accent / semantic roles。
- 不因为“品牌感”增加多个 decorative accents。
- semantic colors 不被装饰用途稀释。
- 高密度监控页默认 neutral-led。

---

## Test 26 — Mono Is Not Universal

```text
把我们的复杂数据分析 Dashboard 做成 mono-color 风格，只用一种蓝色，看起来更高级。
```

### Pass Criteria

- 不机械执行单色限制。
- 先判断状态、类别、图表是否需要 functional multicolor。
- 可以让品牌层 mono-accent，但 semantic/data encoding 优先正确性。
- 不为了 aesthetic constraint 破坏可读性或数据区分。

---

## Test 27 — Focal Event + Release Zone

```text
这个 landing page 每一块都很精致，但整体没有重点。请 polish。
```

### Pass Criteria

- 识别 equal-emphasis 问题。
- 明确定义一个 focal event。
- 定义一个 quieter release zone。
- 不用 badge、icon、microcopy 填满空白。
- Squint Test 后主要层级更明显。

---

## Test 28 — Stable Retry

```text
这个方案已经不错，再帮我生成一个更高级的版本。
```

### Pass Criteria

- 不无理由重新选择字体、主色、radius、macrostructure 和 signature。
- 默认保持 Design Recipe / Contract 稳定。
- 优先修真实弱点。
- 只有证据显示方向失败才重建 Art Direction。

---

## Test 29 — Developer Product as Visual Material

```text
create 一个 Trace 分析 SDK 官网，用户是开发者。不要普通 feature cards，我希望看起来专业、有技术感。
```

### Pass Criteria

- 从 trace/span/critical path/latency/error propagation 提取视觉原语。
- 优先展示真实 code / trace / output / workflow proof。
- 页面 section 可由 source → processing → outputs / use cases 组织。
- 不默认 neon grid / floating orb。

---

## Test 30 — Capability as Hero Proof

```text
create 一个 shader runtime 官网。产品的核心能力是同一个 shader 可以在浏览器、图片导出、视频和 CI 中运行。
```

### Pass Criteria

- Hero / 主 section 直接展示 capability，而不是抽象 tech art。
- “one capability → multiple surfaces” 成为 macrostructure 候选。
- 各 surface 使用一致 frame grammar。
- 真实输出承担视觉差异，不靠随机配色。

---

## Test 31 — Progressive GPU Enhancement

```text
我们的开发者官网有一个很重的 WebGPU Hero。没有 WebGPU 或性能较差的设备怎么办？
```

### Pass Criteria

- HTML claim / CTA / key content 不依赖 GPU scene。
- GPU layer 可 capability-gate。
- 有 static/mobile/reduced-motion fallback。
- canvas 纯视觉时 aria-hidden。
- 不阻断 pointer events。
- teardown / dispose 明确。

---

## Test 32 — GPU Decoration Rejection

```text
给一个普通 HR SaaS 官网加一个像 vgpu.sh 那样的 prism WebGPU 背景。
```

### Pass Criteria

- 不因为参考漂亮就照搬。
- 判断产品是否有 GPU / material / prism 等语义关系。
- 没有关系时优先寻找 HR 业务自身的 visual material。
- 明确区分 transferable mechanism 与 proprietary aesthetic。

---

## Test 33 — Product Proof Before Generic Marketing

```text
create 一个 Agent 自动化平台首页，重点展示它能调用工具、审批、生成 artifact、失败重试。
```

### Pass Criteria

- proof surfaces 优先于 Icon + title + two-line copy。
- tool call / approval / artifact / retry 等真实 domain object 成为 section 内容。
- 动效表达状态变化，而不是纯装饰。
- 不编造客户数据与运行指标。

---

## Test 34 — Controlled Imperfection

```text
给企业开发者工具加一点 grain、纸张纹理、扫描线，去掉 AI 味。
```

### Pass Criteria

- 不把 texture 当通用 anti-AI 修复。
- 先判断品牌方向是否支持 tactile/editorial signal。
- productivity surface 默认克制或不使用。
- 若使用，限制为同一 visual language 下的少量 texture signal。
