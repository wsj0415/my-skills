# Prompt 评分示例

## 分维度示例

### Clarity（清晰度）

#### 低分示例 (3/10)
> 处理一下数据

**问题分析：**
- "处理"是什么操作？清洗、转换、分析、可视化？
- "数据"指什么？文件、数据库、API 响应？
- 没有成功标准

#### 高分示例 (9/10)
> 请清洗这个 CSV 文件中的用户数据：
> 1. 删除 email 列为空的行
> 2. 将 age 列的负值替换为中位数
> 3. 将结果保存为 cleaned_users.csv

---

### Specificity（具体性）

#### 低分示例 (2/10)
> 写个快速排序

**问题分析：**
- 什么语言？
- 输入规模多大？
- 需要性能分析吗？
- 需要测试吗？

#### 高分示例 (9/10)
> 用 Python 实现快速排序：
> - 处理 10 万元级整数数组
> - 时间复杂度 O(n log n)
> - 包含 3 个单元测试用例
> - 对比内置 sorted() 的性能差异

---

### Context（上下文）

#### 低分示例 (2/10)
> 这个按钮为什么不工作？

**问题分析：**
- 什么项目？什么技术栈？
- "这个按钮"是哪个按钮？
- 期望行为是什么？
- 实际行为是什么？

#### 高分示例 (9/10)
> 在我们的 React 电商项目中，购物车页面的"立即结算"按钮点击后没有反应。
> 
> **技术栈**：React 18 + Redux Toolkit + TypeScript
> **期望行为**：跳转到 /checkout 页面
> **实际行为**：点击后无任何反应，控制台无错误
> **已排查**：确认 onClick 处理器已绑定， Redux state 正常

---

### Constraints（约束条件）

#### 低分示例 (2/10)
> 设计一个用户登录系统

**问题分析：**
- 安全要求？
- 性能要求？
- 兼容性要求？
- 技术选型限制？

#### 高分示例 (9/10)
> 设计一个用户登录系统：
> 
> **安全约束**：
> - 密码 bcrypt 加密
> - JWT token 过期时间 2 小时
> - 支持 2FA
> - 防暴力破解（5 次失败锁定 15 分钟）
> 
> **技术约束**：
> - 后端：Node.js + Express
> - 数据库：PostgreSQL
> - 缓存：Redis（存储 token 黑名单）
> 
> **性能要求**：
> - 登录接口 P99 < 500ms
> - 支持 1000 并发

### Output Format（输出格式）

#### 低分示例 (2/10)
> 给我讲讲微服务架构

**问题分析：**
- 要多长？
- 要代码示例吗？
- 要对比单体架构吗？
- 要实践建议吗？

#### 高分示例 (9/10)
> 请写一份微服务架构入门指南：
> 
> **输出结构**：
> 1. 微服务 vs 单体架构（对比表格）
> 2. 核心概念解释（每个配 1 个例子）
> 3. 适用场景（3-5 条）
> 4. 常见陷阱（3-5 条）
> 
> **格式要求**：
> - Markdown 格式
> - 总字数 1500-2000 字
> - 技术术语首次出现时加英文注释

#### 高分示例 (9/10)

> - 从代码质量角度评价
> - 指出潜在 bug

### Examples（示例）

#### 低分示例 (2/10)
> 帮我写一些友好的错误提示

**问题分析：**
- 没有给出"友好"的参考标准
- 不知道想要什么风格

#### 高分示例 (9/10)
> 帮我写一些友好的错误提示，参考下面风格：
> 
> **好例子**：
> - "哎呀，这个邮箱格式好像不太对，请检查后再试一次～"
> - "密码强度不够哦，需要至少 8 位，包含大小写字母和数字"
> 
> **坏例子**：
> - "Invalid input"
> - "Error 400"
> 
> 请为以下场景写提示：
> 1. 手机号格式错误
> 2. 验证码过期
> 3. 网络超时

### Chain-of-thought（推理链）

#### 低分示例 (2/10)
> 分析一下我们的用户留存率为什么下降

**问题分析：**
- 没有引导分析框架
- AI 可能直接给结论，缺少推理过程

#### 高分示例 (9/10)
> 分析一下我们的用户留存率为什么下降。
> 
> **请按以下步骤分析**：
> 1. 先列出可能影响留存的 5-8 个因素类别（产品、市场、竞争等）
> 2. 对每个因素，说明如何验证（需要什么数据）
> 3. 根据我们已有的数据，逐一排除或确认
> 4. 给出最可能的 3 个原因，按可能性排序
> 5. 对每个原因给出验证假设和下一步行动

## 完整 Prompt 对照示例

### 案例 1：从 15 分到 72 分

#### 原始 Prompt (15/80)
> 帮我优化一下这个接口

#### 评分详情
| 维度 | 得分 | 原因 |
|------|------|------|
| Clarity | 3/10 | "优化"不明确（性能？代码质量？） |
| Specificity | 2/10 | 无具体指标 |
| Context | 2/10 | 无项目背景 |
| Constraints | 2/10 | 无约束条件 |
| Output format | 2/10 | 无格式要求 |
| Role | 1/10 | 无角色定义 |
| Examples | 1/10 | 无示例 |
| CoT | 2/10 | 无推理引导 |

#### 优化后 Prompt (72/80)
> 请作为资深后端工程师，优化下面这个用户查询接口的性能。
> 
> **背景**：
> - 这是我们的电商用户中心 API
> - 当前 QPS 约 500，P99 延迟 800ms
> - 数据库是 MySQL 8.0，数据量 500 万行
> 
> **优化目标**：
> - P99 延迟降到 200ms 以内
> - 保持查询功能不变
> 
> **请按以下步骤**：
> 1. 分析当前 SQL 的执行计划
> 2. 指出 3-5 个性能瓶颈
> 3. 给出优化方案（索引/查询改写/缓存）
> 4. 输出优化后的完整代码
> 
> **约束**：
> - 不能改变 API 响应格式
> - 只能使用项目现有依赖（见 requirements.txt）
> 
> ```python
> [原始代码]
> ```

### 案例 2：从 28 分到 68 分

#### 原始 Prompt (28/80)
> 写个正则匹配邮箱

#### 评分详情
| 维度 | 得分 | 原因 |
|------|------|------|
| Clarity | 5/10 | 目标基本清楚，但"匹配"含义模糊 |
| Specificity | 3/10 | 无语言、无测试用例 |
| Context | 2/10 | 无使用场景 |
| Constraints | 3/10 | 无格式验证规则 |
| Output format | 3/10 | 只说"写个正则" |
| Role | 1/10 | 无角色 |
| Examples | 1/10 | 无示例邮箱 |
| CoT | 2/10 | 无推理引导 |

#### 优化后 Prompt (68/80)
> 请写一个邮箱验证正则表达式。
> 
> **使用场景**：前端表单验证，用户注册时检查邮箱格式
> 
> **验证规则**：
> - 必须包含 @ 符号
> - @ 前面至少 1 个字符
> - @ 后面必须是有效域名（至少 1 个点，点后 2-6 个字母）
> - 支持常见特殊字符：. _ + -
> 
> **要求**：
> - 语言：JavaScript
> - 输出：正则 + 测试函数
> - 包含 10 个测试用例（5 个有效 +5 个无效）
> 
> **参考有效邮箱**：
> - test@example.com
> - user.name+tag@domain.co.uk
> - a@b.cn
> 
> **参考无效邮箱**：
> - @example.com
> - test@
> - test@.com
