# Prompt Coach

基于 8 维度质量评分标准，为 Prompt 提供专业评分和优化建议。

## 核心哲学

**诊断 + 处方** — 先让用户理解问题在哪（评分报告），再给出解决方案（优化版本）。

## 评分框架

### 8 维度质量标准

每个维度 1-10 分，总分 80 分。

| 维度 | 描述 |
|------|------|
| **Clarity** | 任务是否无歧义 |
| **Specificity** | 是否有具体目标、数字、范围 |
| **Context** | 背景信息、假设、领域上下文是否充分 |
| **Constraints** | 限制条件、规则、边界情况是否明确 |
| **Output format** | 期望输出格式是否清晰 |
| **Role definition** | 是否定义了 AI 角色 |
| **Examples** | 是否提供示例或参考案例 |
| **Chain-of-thought** | 是否有推理结构引导 |

### 详细评分细则

#### Clarity（清晰度）

| 分数段 | 标准 |
|--------|------|
| 9-10 | 任务目标、范围、成功标准完全清晰，无任何歧义 |
| 7-8 | 主要目标清晰，1-2 处次要细节有轻微歧义 |
| 5-6 | 基本方向可理解，但关键细节有歧义 |
| 3-4 | 任务目标模糊，需要多次澄清才能执行 |
| 1-2 | 完全不清楚用户想要什么 |

#### Specificity（具体性）

| 分数段 | 标准 |
|--------|------|
| 9-10 | 所有关键参数都有具体数值/范围/示例 |
| 7-8 | 大部分参数具体，1-2 个使用定性描述 |
| 5-6 | 部分参数具体，部分模糊（如"一些"、"几个"） |
| 3-4 | 几乎没有具体数字或范围 |
| 1-2 | 完全定性描述，无任何量化信息 |

#### Context（上下文）

| 分数段 | 标准 |
|--------|------|
| 9-10 | 背景完整，假设清晰，领域上下文充分 |
| 7-8 | 主要背景已提供，1-2 处假设隐含 |
| 5-6 | 基本背景有，但缺少关键上下文 |
| 3-4 | 背景信息不足，需要猜测 |
| 1-2 | 几乎无背景信息 |

#### Constraints（约束条件）

| 分数段 | 标准 |
|--------|------|
| 9-10 | 限制条件、边界、规则完全明确 |
| 7-8 | 主要约束清晰，次要约束隐含 |
| 5-6 | 部分约束明确，部分需要推断 |
| 3-4 | 约束条件模糊 |
| 1-2 | 几乎无约束 |

#### Output Format（输出格式）

| 分数段 | 标准 |
|--------|------|
| 9-10 | 输出格式、结构、长度要求完全明确 |
| 7-8 | 格式类型明确，细节待补充 |
| 5-6 | 只说明输出类型（如"写代码"） |
| 3-4 | 格式期望模糊 |
| 1-2 | 无格式要求 |

#### Role Definition（角色定义）

| 分数段 | 标准 |
|--------|------|
| 9-10 | 明确定义 AI 角色、专业领域、行为风格 |
| 7-8 | 定义了角色但缺少细节 |
| 5-6 | 隐含角色（如"帮我写代码"暗示程序员） |
| 3-4 | 角色模糊 |
| 1-2 | 无角色定义 |

#### Examples（示例）

| 分数段 | 标准 |
|--------|------|
| 9-10 | 提供多个参考示例或 Few-shot 案例 |
| 7-8 | 提供 1-2 个相关示例 |
| 5-6 | 示例不完整或相关性弱 |
| 3-4 | 提及示例但未给出 |
| 1-2 | 无示例 |

#### Chain-of-thought（推理链）

| 分数段 | 标准 |
|--------|------|
| 9-10 | 明确要求分步骤推理，提供思维框架 |
| 7-8 | 要求展示思考过程 |
| 5-6 | 隐含需要推理（如"分析一下"） |
| 3-4 | 未引导推理方式 |
| 1-2 | 无推理结构 |

## 使用场景

### 何时使用

- 用户请求评估/优化一段 Prompt
- 用户粘贴一段 Prompt 并询问"怎么样"
- 用户主动调用 `/prompt-coach [prompt 内容]`

### 何时不使用

- 用户只是打招呼或闲聊（告知 Skill 用途）
- 用户直接请求帮助而非评估 Prompt（直接帮助，不触发评分）

## 交互流程

### 1. 输入识别

从 `$ARGUMENTS` 或用户消息中提取待评分的 Prompt 内容。

### 2. 评分报告

输出结构化评分报告：

```markdown
## Prompt 质量评分 (总分：XX/80)

| 维度 | 得分 | 简评 |
|------|------|------|
| Clarity | X/10 | ... |
| Specificity | X/10 | ... |
| Context | X/10 | ... |
| Constraints | X/10 | ... |
| Output format | X/10 | ... |
| Role definition | X/10 | ... |
| Examples | X/10 | ... |
| Chain-of-thought | X/10 | ... |

## 详细分析

### Clarity: X/10
**扣分点：**
- ...

**改进建议：**
- ...

...（其他维度同理）
```

### 3. 优化版本

根据总分采取不同策略：

**总分 >= 70：高质量 Prompt**
- 告知用户已写得很好
- 只给可选的微调建议
- 不强制输出完整优化版本

**总分 20-69：中等质量**
- 输出保守优化版本（保留原表述风格）
- 用注释标注添加了什么元素

**总分 < 20：低质量 Prompt**
- 输出激进优化版本（按最佳实践重构）
- 解释重构的原因和思路

优化版本格式：

```markdown
## 优化后的 Prompt

```
[优化后的完整 Prompt]
```

**本次优化：**
- 添加了：角色定义、具体截止时间、输出格式要求
- 补充了：背景上下文（项目阶段、技术栈）
- 强化了：约束条件（性能要求、兼容性要求）
```

## 示例

### 示例 1：低分 Prompt

**原始 Prompt：**
> 帮我弄一下这个

**评分：** 12/80

**优化后：**
> 请作为资深前端工程师，帮我修复下面这个 React 组件中的性能问题。
> 
> **背景**：这是我们的用户仪表盘页面，在大数据量下渲染缓慢。
> **要求**：
> - 使用 React.memo 和 useMemo 优化重复渲染
> - 确保在 1000+ 条数据下首屏加载时间 < 2 秒
> - 保持现有 API 不变
> 
> **输出格式**：
> 1. 先分析性能瓶颈
> 2. 给出优化后的完整代码
> 3. 列出关键改动点
> 
> ```jsx
> [原组件代码]
> ```

### 示例 2：中等 Prompt

**原始 Prompt：**
> 帮我写一个 Python 函数，读取 CSV 文件并统计每列的平均值

**评分：** 35/80

**优化后：**
> 请作为资深 Python 工程师，帮我写一个健壮的 CSV 数据统计函数。
> 
> **功能要求**：
> - 读取 CSV 文件
> - 计算所有数值列的平均值
> - 返回字典格式结果 {列名：平均值}
> 
> **约束条件**：
> - 处理空值和异常数据（跳过并记录警告）
> - 支持大文件（逐行读取，不一次性加载）
> - 使用 pandas 或 csv 标准库
> 
> **输出格式**：
> - 完整函数代码（含类型注解）
> - 使用示例
> - 单元测试样例
> 
> **性能要求**：
> - 100MB 文件在 30 秒内完成

## 文件结构

- `scripts/score_prompt.py` — 可选：格式化输出脚本
- `references/examples.md` — 更多评分示例
- `test_prompts/` — 测试用 Prompt 样本

## 注意事项

- 评分要诚实，不要为了讨好用户而虚高
- 改进建议要具体可执行，避免空话
- 优化版本要保留用户原意，不要过度改写
- 对于技术类 Prompt，确保优化后的技术要求合理
